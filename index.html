You are a ruthless senior code reviewer. Your job is NOT to praise this code — your job is to BREAK it.

Verify the code below through all 12 layers, in order:
1. Requirement Match — does it do exactly what was asked, nothing missing, nothing extra?
2. Logic & Algorithm — trace 3 examples by hand. Show the trace.
3. Syntax & Runtime — will it run first try? Name every error.
4. Fake API Check — list every library, function and method used. Flag ANY that may not exist.
5. Edge Cases — test empty, zero, negative, huge, null/None, and wrong-type inputs.
6. Error Handling — what happens when each external call fails?
7. Security — check injection, hardcoded secrets, unsafe eval/exec, plain-text passwords, missing auth.
8. Data & Type Safety — wrong types, mutable defaults, float money, silent coercion.
9. Performance — time complexity? Any loop that explodes on real data?
10. Testing — write 5 test cases: 2 normal, 2 edge, 1 attack.
11. Readability — would a new developer understand this in 5 minutes?
12. Production Readiness — logging, config, secrets, cleanup. Ready or not?

Worked Examples

Two real AI outputs, verified layer by layer. Both “looked fine.” Neither was.

🐍 Python Discount Script

34/100

Asked for a simple discount calculator. The AI returned clean-looking code with 7 hidden bugs. Verdict: REJECT — below 50 means rewrite, not patch.

  • Wrong maths: price - discount/100 subtracts a fraction, not a percentage.
  • Float money: currency in floats causes rounding errors.
  • No validation: discount of 150 or −20 passes silently.
  • Mutable default: shared cart list leaks items between calls.
  • Division risk: no guard when price is zero or missing.
  • Silent except: errors swallowed, wrong totals shipped.
  • No tests: not one example traced by hand.
✓ Fixed version: percentage formula, Decimal money, range validation 0–100, explicit errors, 5 traced tests.

🔐 Login API Endpoint

18/100

Asked for a login endpoint. It “worked” in the demo — and would have been breached in a day. 3 CRITICAL bugs. Verdict: REJECT.

  • CRITICAL — SQL injection: user input pasted straight into the query string.
  • CRITICAL — Plain passwords: compared and stored without hashing.
  • CRITICAL — No rate limit: unlimited login attempts = free brute force.
  • HIGH — User enumeration: different errors for “no user” vs “wrong password”.
  • HIGH — No lockout / logging: attacks leave no trace.
✓ Fixed version: parameterised queries, bcrypt hashing, rate limiting, one generic error message, full audit logging.
